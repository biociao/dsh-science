# 并行委派（Delegation）

Claude Science 会把请求拆成并行轨道；这里用 subagent 实现同样的机制。

## 何时拆分

- 多个**相互独立**的任务（样本 A/B/C 各自分析；基因 X/Y/Z 各自检索；假设 H1/H2 各自检验）
- 任务之间无共享可变状态（不写同一个文件）
- 单个任务量大到值得一个独立上下文

## 拆分协议

1. **设计轨道**：在 todo_write 中列出每条轨道（每条一个 in_progress 或多个并行）。
2. **每条轨道独立目录**：`analyses/tracks/<track-name>/`（或对应 experiments/<id>/），轨道内自包含：README.md（任务说明）、输入、输出。
3. **启动**：用 `subagent`（后台，run_in_background 默认）逐条启动；prompt 必须自包含：
   - 任务目标与验收标准
   - 输入文件路径（绝对路径）
   - 输出写入哪个目录、什么格式
   - 约束（运行环境、不要改哪些文件、不要联网除非必要）
   - 完成回报格式（结果摘要 + 产物路径 + 遗留问题）
4. **并行度**：可同时启动多条；注意共享资源（同一 conda 环境、磁盘 IO、数据库查询限流）。

## 合并协议

1. 全部轨道完成后，逐条检查回报与产物（文件存在、格式正确）。
2. 汇总写入 `analyses/tracks/SUMMARY.md`：每条轨道的结果、质量评估、不一致处。
3. 重要结果统一 `artifact_save` 归档（含各轨道产物）。
4. 轨道间结论冲突 → 不掩盖，列为待解决问题，必要时开一轮专门实验。

## 评审联动

跨轨道合并出的关键论断，走 scientific-reviewer 评审（子代理核查各轨道执行记录）。

## 纪律

- 轨道失败不静默：记录到 SUMMARY.md 的"遗留问题"，能降级（换工具/换数据）则降级。
- 不要用并行轨道做需要全局状态的工作（清单、索引更新由主会话串行完成）。
- 轨道 prompt 里给足上下文（子代理看不到本会话历史）。
